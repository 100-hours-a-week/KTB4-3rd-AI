# 모니터봇 사용법

## 사용자 역할(관리자·팀원)

텔레그램·디스코드 권한은 세 가지다(ops_agent/roles.py).

| 역할 | 정하는 방법 | 쓸 수 있는 것 |
| --- | --- | --- |
| admin(관리자) | 환경변수 Admin_Telegram_ID·Admin_Discord_ID에 있는 사용자 ID. 쉼표로 구분한 목록이며 인원 제한 없음 | 모든 명령·버튼 |
| member(팀원) | 텔레그램: /join으로 가입 요청 → 관리자 승인(tg_members status=approved). 디스코드: 설정한 채널에 글을 쓸 수 있으면 팀원 | 관리자 전용을 뺀 명령·버튼 |
| 미등록 | 그 밖의 사용자 | /join만 |

- 관리자 전용: /request(가입 요청 목록), 가입 승인·거절 버튼, /drill guess, 문서 올리기·/docs·문서 [삭제], 문서 정정 요청과 그 [저장].
- 미등록 사용자의 다른 메시지·버튼은 무시한다. 팀원이 관리자 전용을 쓰면 "권한이 없습니다"로 답한다.
- 알림·리포트는 관리자와 승인된 팀원의 채팅방, 디스코드 채널로 보낸다.
- 텔레그램·디스코드 수신은 리더 태스크 1개만 한다. 디스코드 채널의 /join은 "이미 등록된 사용자입니다"로 답한다.

## 명령 목록

/help가 보여 주는 명령이다(channels/telegram/render.py HELP, receiver.py).

| 명령 | 뜻 | 권한 |
| --- | --- | --- |
| /status | 상태: DB 확인, 열린 장애 수, 활성 조정 수, 지식 수, 오늘 토큰(훈련 따로), 리더 여부, 태스크 | 관리자·팀원 |
| /flags | 활성 조정: knob, 값, 만료 시각, 설정 주체 | 관리자·팀원 |
| /knowledge [검색어] | 장애 지식 목록(제목·ID·버전) | 관리자·팀원 |
| /trace <request_id> | 요청 1건 추적 | 관리자·팀원 |
| /drill start <id> · stop · guess <원인 설명> | 모의 장애 훈련(dev·local) | start·stop 관리자·팀원, guess 관리자 |
| /join | 가입 요청 | 누구나 |
| /request | 대기 중인 가입 요청 목록 | 관리자 |
| /docs, /docs <이름> | 문서 목록, 문서의 절 목록과 [삭제] | 관리자 |
| /help | 명령 안내 | 관리자·팀원 |

- 모르는 명령이나 /drill 뒤 하위 명령이 틀리면 /help 내용을 보낸다.
- 명령이 아닌 메시지는 챗봇이 답한다.

## 버튼 종류

| 버튼 | 붙는 메시지 | 동작 |
| --- | --- | --- |
| [저장] [취소] | 지식 정리본(24시간 유효), 문서 절 정정본 | 저장하면 반영, 취소하면 버림 |
| [승인] [거절] | 조정 제안 | 승인하면 조정 적용, 거절하면 기록만 |
| [즉시 원복] | 조정 효과 "효과 없음" 결과 | 조정 값을 바로 되돌림 |
| [승인 · 이름] [거절] | /request 가입 요청 목록 | 가입 승인·거절 |
| [삭제] | /docs <이름>의 문서 상세(업로드 문서만) | 그 문서 전체 삭제 |

- 버튼을 누르면 "처리 중"을 먼저 띄운다.
- 처리 후 버튼은 "✅ 저장 · 누른 사람"처럼 처리 결과 표시로 바뀐다. 같은 건으로 여러 사람에게 보낸 메시지의 버튼도 모두 바뀐다.
- 관리자가 여러 명이면 먼저 누른 사람의 처리만 반영된다. 이미 처리된 건이면 "이미 처리했거나 없는 …"으로 답한다.

## 팀원 가입 절차

1. 사용자가 봇에 /join을 보낸다. 표시 이름과 @username이 함께 기록된다(status=pending).
   - 이미 대기 중이면 "이미 승인 대기 중입니다", 관리자나 승인된 팀원이면 "이미 등록된 사용자입니다".
2. 관리자가 /request로 대기 목록(이름, @username, user ID, chat ID, 요청 시각)을 본다.
3. 관리자가 [승인 · 이름] 또는 [거절]을 누른다.
4. 승인하면 그 사용자에게 "✅ 가입이 승인되었습니다. /help로 명령을 확인하세요"를 보낸다.
5. 거절하면 기록을 지우고 "가입이 거절되었습니다. 다시 요청하려면 /join"을 보낸다. 다시 요청할 수 있다.

## 대화와 답장

- 질문·/trace·문서 올리기를 보내면 먼저 "🔎 접수 · 대기 n번째"가 오고, 답이 나오면 그 메시지가 답으로 바뀐다.
- 사람 메시지는 20건까지 줄을 세운다. 넘치면 "⏳ 대기열이 가득 찼습니다(20건)", 같은 글을 60초 안에 다시 보내면 "같은 질문을 처리 중입니다"로 답한다.
- 지난 대화는 텔레그램·디스코드를 함께 찾는다. 참고만 하고 사실 근거로 쓰지 않으며, 답에서 말할 때는 출처(메신저·시각)를 밝힌다.
- 알림·리포트·진단 메시지에 답장하면 그 장애를 문맥으로 대화한다("↩ 답장하면 이 장애로 대화합니다").
- 답은 근거가 있으면 "근거 N개"를 접힌 인용으로 붙인다.
- 지식 추가·수정·삭제는 대화로 요청하면 정리본(제목, 신호, 원인, 조치, 확인할 곳, 이유)과 [저장][취소]가 온다. 정리본은 24시간 유효하다.
- [저장]하면 "✅ 지식을 저장했습니다 · 제목 · ID vN"으로 답한다. 임베딩에 실패하면 저장하지 않고 정리본을 그대로 두므로 [저장]을 다시 누르면 된다.
- 훈련 장애에 답장하면 "훈련 장애라 대화·지식 저장 대상이 아닙니다"로 답한다.
- 대화 문맥은 대화방별 압축 요약과 그 뒤의 원문이다. 원문이 약 8,000토큰을 넘으면 오래된 턴을 요약에 합쳐 4,000토큰 이하로 줄인다.
- 답 끝에는 근거가 있는 "예상 문제 → 해결 (근거)"를 붙이고, 근거가 없으면 그 칸을 뺀다.

## /trace 요청 추적

- 사용: `/trace <request_id>`. request_id는 응답 헤더 X-Request-ID 값이고 서버 로그의 `request_id=`와 같다.
- 모니터가 기록한 요청 결과(request_results)와 그 요청의 LLM 호출(llm_calls)을 근거로 챗봇이 답한다.
- 요약 내용: 기능, 결과(ok·fail), 응답 코드, 단계(step_id), 사유(reason), 처리 경로(route와 사유), 지연 시간(ms), LLM 호출 수.
- 기록이 없으면 "<request_id> 기록 없음(30일 보존, 사용자 단위 추적 안 함)"이다.
- 알림 메시지의 "샘플: /trace <id>" 줄에서 바로 쓸 수 있다.
- 기능 스위치 F4가 켜진 스테이지에서만 동작한다.

## /drill 모의 장애 훈련

- 훈련은 drill=true인 스테이지(local, dev)에서만 된다. stg·prod는 "<stage>에서는 훈련을 할 수 없습니다".
- `/drill start <id>`: 시나리오 ID는 `S-` + 16진수 4자리(예: S-7a1c). 진행 중인 훈련이 있으면 시작하지 않는다. 시작하면 주입 플래그를 걸고 합성 요청 20건을 15초 간격으로 보낸다(X-Request-ID가 `drill-`로 시작). 주입 플래그는 6분(360초) 뒤 만료된다.
- `/drill stop`: 주입 플래그를 지우고 훈련을 끝낸다. 묶음 C(정상 상황)면 오탐 여부를 채점 1행으로 남긴다. 그 밖은 비교 실행 9건(single·rag·agent 각 3회)을 60초 간격으로 예약한다.
- `/drill guess <원인 설명>`: 관리자가 원인 추정을 기록한다. 두 번까지 기록하고 정답 원인과 비교해 판정한다.
- 훈련 알림에는 "[훈련]" 표시가 붙는다.

## 문서 올리기와 관리

관리자용 문서 기능이다.

- 관리자가 봇에 파일을 보내면 바로 파싱해 저장한다. 형식: md, txt, pdf, docx. 크기: 20MB 이하.
- 저장 후 봇은 절 개수를 네 가지로 답한다.
  - 새것(new): 새로 넣은 절
  - 같음(same): 이미 넣은 절과 같은 절
  - 겹침(overlap): 다른 문서의 절과 거의 같은 절. 저장하고 표시만 한다
  - 삭제(removed): 이전 버전에 있었고 이번 파일에는 없는 절
- `/docs`: 문서 목록
- `/docs <이름>`: 그 문서의 절 목록과 문서 전체 [삭제] 버튼(업로드 문서만)
- 저장소에서 온 문서(origin=repo)는 봇에서 삭제·수정할 수 없다. git에서 고친다.
- 절을 고치려면 대화로 요청한다(예: "…문서 …절 고쳐줘"). 봇이 고친 본문과 [저장][취소]를 보낸다.
- 문서는 Qdrant `<stage>_docs` 컬렉션에만 저장된다.
