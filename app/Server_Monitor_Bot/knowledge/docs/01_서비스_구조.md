# 서비스 구조

## 엔드포인트 목록

FastAPI 이미지 판독 서비스가 여는 경로다(app/api/router.py, app/main.py).

| 경로 | 용도 | 처리 기능(feature) |
| --- | --- | --- |
| POST /taxi_meter | 택시 미터기 사진에서 현재 요금(cost)을 읽는다 | taxi_meter |
| POST /receipt | 송금 영수증에서 금액·이체 결과·받는 사람·보낸 시각을 읽는다 | receipt |
| GET /health | 프로세스가 떠 있으면 200 `{"status":"ok"}`. 키·모델 상태와 무관 | - |
| GET /metrics | Cloud Prometheus 수집용 지표. /health·/metrics 요청은 지표에서 뺀다 | - |

- 두 판독 API는 사진을 본문으로 받지 않고 `image_URL`을 서버가 GET한다.
- 두 판독 API 요청은 모두 내부 큐(app.state.scheduler)를 거친다. 라우터는 `scheduler.submit(kind, image_URL)` 결과를 그대로 응답 모델에 담는다.

## 처리 단계(step_id) 11개

단계 이름은 app/Server_Monitor_Bot/knowledge/schema.py의 STEPS다. 한글 이름은 render.py STEPS, 응답 코드 대응은 hooks/assemble.py CODE_STEP 기준이다.

| step_id | 한글 이름 | 뜻 | 최종 응답 코드 |
| --- | --- | --- | --- |
| request_validate | 요청 검증 | 요청 JSON·image_URL 검사 | REQUEST_INVALID |
| image_fetch | 이미지 다운로드 | image_URL GET | IMAGE_FETCH_FAILED |
| image_validate | 이미지 검사 | 크기·형식 검사 | IMAGE_SIZE_INVALID, IMAGE_TYPE_INVALID |
| model_ready | 모델 준비 | 키·모델·Modal 준비 상태 | MODEL_NOT_READY |
| pipe_ocr | OCR | GPU 경로의 OCR·모델 실행 | (대체 처리 시작 단계로만 기록) |
| pipe_judge | 로컬 판독 | openjev 판정 | (대체 처리 시작 단계로만 기록) |
| luna_call | OpenAI 호출 | luna(OpenAI) 호출 | UPSTREAM_FAILED |
| luna_parse | 응답 해석 | luna 출력 검사·값 확정 | JUDGE_PARSE_FAILED |
| respond | 응답 | 정상 응답 | OK(200) |
| unhandled | 처리되지 않은 오류 | AppError가 아닌 예외 | INTERNAL |
| queue_wait | 대기열 | 내부 큐 대기·실행 합계가 상한 초과 | QUEUE_TIMEOUT |

- 요청 결과(request_results)의 step_id는 최종 응답 코드로 정해진다. pipe_ocr·pipe_judge는 fallback_step(대체 처리가 시작된 단계)에만 쓰인다.

## 대체 처리 단계(fallback_step) 대응

GPU 경로에서 luna로 넘길 때 남는 사유(route_reason)와 대체 처리 시작 단계의 대응이다(hooks/assemble.py FALLBACK_STEP).

| route_reason | fallback_step |
| --- | --- |
| model_not_ready | model_ready |
| upstream_failed | pipe_ocr |
| internal | pipe_ocr |
| judge_fallback | pipe_judge |

- route_reason이 위 네 값 중 하나면 fallback=true로 기록한다.
- device_off, force_luna, route_api는 대체 처리로 세지 않는다(fallback=false).

## 내부 큐 배분(API 큐와 GPU 큐)

app/inner_queue/scheduler.py의 Scheduler가 모든 판독 요청을 배분한다.

| 상수 | 값 | 뜻 |
| --- | --- | --- |
| TOTAL | 30 | 전체 자리(대기+처리 중) |
| API | 20 | API 큐 상한 |
| GPU | 10 | GPU 큐 상한(TOTAL - API) |
| DEADLINE | 60.0초 | BE read-timeout |
| MIN_LEFT | 30.0초 | 남은 시간이 이보다 적으면 실행하지 않음 |

- 배분 규칙: API 큐 개수가 20 미만이면 api, 아니면 gpu(`route = "api" if count["api"] < api else "gpu"`). 평소 요청은 API 큐(luna)로 간다.
- 전체 자리 30개가 모두 차면 자리가 날 때까지 기다린다. 자리를 기다린 시간도 기한에 들어간다.
- 워커는 API 큐 16개, GPU 큐 1개이고 워커마다 한 건씩 실행한다. API 큐는 kind별 run_api, GPU 큐는 run_gpu를 부른다.
- DEVICE=off(GPU 없음)면 전체 자리 30을 모두 API 큐에 준다.
- 실행 직전 `60 - 대기 시간 < 30`이면 실행하지 않고 QUEUE_TIMEOUT(504)을 준다. 실행 중에도 대기와 실행을 합쳐 60초를 넘기면 호출을 취소하고 같은 504를 준다. 로컬 ocr·slm의 스레드 추론은 취소해도 끝까지 돈다.
- 기다리던 요청이 취소되면 실행하지 않고 건너뛴다(queue job skipped).

## 경로별 실행(run_api, run_gpu)

app/features/{receipt,taxi_meter}/main.py가 경로별 실행을 맡는다.

- run_api: 이미지를 받은 뒤 바로 luna로 처리한다(route_reason=route_api).
- run_gpu: 이미지를 받은 뒤 아래 순서로 판단한다.
  1. DEVICE가 off면 luna(device_off)
  2. 공유 플래그 route.force_luna가 켜져 있으면 luna(force_luna)
  3. DEVICE가 modal이면 Modal pipe, 로컬 장치면 model_pipe_run 실행
  4. ModelNotReady면 luna(model_not_ready)
  5. InternalError·UpstreamError면 luna(internal 또는 upstream_failed)
  6. 결과가 None(판정 보류)이면 luna(judge_fallback)
  7. 결과가 있으면 그대로 응답(route=pipe)
- DEVICE는 app/core/config.py가 기동 때 정한다: MODAL_TOKEN_ID_1·MODAL_TOKEN_SECRET_1이 둘 다 있으면 modal, 아니고 LOCAL_DEVICE=TRUE면 cuda·mps·cpu 중 쓸 수 있는 것, 둘 다 아니면 off(기본, luna만 사용).

## luna(OpenAI) 경로

luna는 OpenAI Responses API 호출이다(app/llm/providers/openai.py).

- 모델 이름은 코드 고정 `gpt-6-luna`, 이미지 기능은 llm 이름 api_1(키 OPENAI_API_KEY_1)을 쓴다.
- 이미지를 base64 data URL로 넣고, 기능별 JSON 스키마를 Structured Outputs(strict)로 강제한다.
- 미터기 스키마: `cost`(정수 또는 null). null이면 JUDGE_PARSE_FAILED(unreadable).
- 영수증 스키마: `amount_cost`, `transfer_info`, `sender_name`, `send_time`. send_time 외 필드가 null이면 JUDGE_PARSE_FAILED(unreadable).
- 영수증은 transfer_info가 이체 완료 문구일 때만 통과한다. 완료 문구: `완료|보냈`. 아래 표현이 섞이면 완료가 아니다: `실패|취소|않|못|대기|예약|진행 중|처리 중` → JUDGE_PARSE_FAILED(transfer_not_done).
- 금액은 쉼표·공백·"원"을 지운 정수로 바꾼다. 바꿀 수 없으면 not_amount.
- send_time은 날짜와 시각 사이 공백만 보정하고 나머지 표기는 영수증에 적힌 그대로 둔다.

## GPU 경로(pipe) 판정

GPU 경로는 OCR로 원문을 읽고 openjev(NLI 모델)로 후보를 고른다(features/*/pipeline.py, core/oj_decide.py).

- OCR: PaddleOCR, 검출 PP-OCRv6_medium_det, 인식 korean_PP-OCRv5_mobile_rec. 인식 점수 0.6 미만 줄은 버린다.
- openjev: AlexWortega/openjev, subfolder qwen3.5-4b-nli-v2. 후보마다 "{필드}은/는 {후보}이다"를 물어 [모순, 지지, 중립] 점수를 받는다.
- 판정(judge_rows): 1등 지지 점수 ≥ 0.75이고 2등과 차이 ≥ 0.15면 pass, 1등의 모순 점수 ≥ 0.60이면 reject, 그 밖은 review. 후보가 없으면 review.
- 미터기: 100원 이상 금액 후보 중 하나를 고른다. pass가 아니면 None(→ luna).
- 영수증: amount_cost → send_time → transfer_info → sender_name 순서로 판정한다. 하나라도 pass가 아니거나 이체 완료 문구가 아니면 None(→ luna).
- Modal에서는 이 판정 전체가 원격 OjModels.pipe 한 번으로 실행된다(09_GPU_경로 참고).
