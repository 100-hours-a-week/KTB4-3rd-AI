# 로그 카탈로그

## 로그 줄 형식과 head

app/core/logging.py가 로그 형식을 정한다.

- 형식: `<시각> <레벨> <로거 이름> <메시지>`, 시각은 `%Y-%m-%d %H:%M:%S`
- 메시지는 `head: key=value key=value ...` 꼴이다. 실패 로그는 "무엇이 실패: 어디서, 왜(reason), 무엇을 확인(hint)" 순서로 쓴다.
- head는 메시지에서 첫 `:` 앞 문자열이다(hooks/assemble.py split). 모니터는 head로 로그 종류를 구분한다.
- 요청 안에서 남긴 app 로그 끝에는 ` request_id=<id>`가 붙는다. 같은 요청의 로그를 이 값으로 묶는다.
- 이미지 바이트, base64, API 키, 모델 원문, 사람 이름은 로그에 넣지 않는다. URL은 호스트만 남긴다.
- 모니터는 WARNING 이상 로그를 마스킹해 app_logs에 저장한다. INFO 로그는 저장하지 않고 요청 결과 조립에만 쓴다.

예(tests/test_logging.py):
`request failed: path=/taxi_meter status=422 code=REQUEST_INVALID hint=요청 JSON에 문자열 image_URL이 있는지 확인 request_id=spring-123`

## 요청 처리 로그(app/main.py)

| 레벨 | head | 필드 | step_id |
| --- | --- | --- | --- |
| WARNING | request is invalid | path, fields | request_validate |
| INFO | request done | path, status, code, ms | 요청 종료(모든 단계) |
| WARNING | request failed | path, status, code, hint (4xx) | code에 해당하는 단계 |
| ERROR | request failed | path, status, code, hint (5xx) | code에 해당하는 단계 |
| ERROR | unhandled error | path, error. 스택은 로그에만 | unhandled |

- `request done`이 나오면 모니터가 그 request_id의 요청 결과(request_results)를 확정한다.
- request done의 code는 성공이면 OK다.

## 내부 큐 로그(app/inner_queue/scheduler.py)

| 레벨 | head | 필드 | 뜻 |
| --- | --- | --- | --- |
| INFO | queue job routed | kind, route(api\|gpu), api, gpu | 큐 배분 결과와 큐별 개수 |
| INFO | queue job done | kind, route, waited_ms, ran_ms | 실행 끝. 대기·실행 시간 |
| WARNING | queue job expired | kind, route, waited_ms | 대기 상한을 넘겨 실행하지 않고 QUEUE_TIMEOUT. step queue_wait, reason expired |
| INFO | queue job skipped | kind, route, reason=cancelled | 기다리던 요청이 취소돼 실행 안 함 |
| ERROR | unhandled error | kind, route, error | 실행 함수의 AppError가 아닌 예외 → INTERNAL |

## 이미지 로그(features/*/image.py)

receipt와 taxi_meter의 image.py는 같은 로그를 남긴다.

| 레벨 | head | 필드 | step_id |
| --- | --- | --- | --- |
| INFO | image loaded | host, bytes, type, ms | 다운로드·형식 검사 통과 |
| WARNING | image download failed | host, reason, status, ms | image_fetch |
| WARNING | image size is invalid | host, bytes(0 또는 >5MB) | image_validate, reason size |
| WARNING | image must be jpeg or png | host, reason, type 또는 bytes | image_validate |

- image download failed의 reason: timeout, connect, redirect, http_4xx, http_5xx, bad_url(그 밖은 예외 클래스 이름)
- image must be jpeg or png의 reason: not_image(이미지로 열리지 않음), wrong_type(JPEG·PNG 아님)

## 경로·판정 로그(features/*/main.py, pipeline.py)

| 레벨 | head | 필드 | 뜻 |
| --- | --- | --- | --- |
| INFO | request route | route=pipe, device | GPU 경로 결과로 응답 |
| INFO | request route | route=luna, reason | luna로 처리. reason: route_api, device_off, force_luna, model_not_ready, internal, upstream_failed, judge_fallback |
| WARNING | image model failed | code, device | OCR·openjev·Modal 실행 실패로 luna로 넘김 |
| INFO | judge parsed | amount_cost 또는 cost | pass 결과로 응답을 만듦 |
| INFO | judge fallback | 멈춘 필드와 status, 또는 transfer_info=not_done | pass가 아니라 luna로 넘김 |
| WARNING | model output is not valid | field, reason | luna 응답으로 값을 확정 못함 → luna_parse |

- model output is not valid의 reason: not_json, unreadable, not_amount, transfer_not_done
- 테스트 예: `field=cost reason=unreadable`, `field=amount_cost,sender_name reason=unreadable`, `field=transfer_info reason=transfer_not_done`

## OpenAI(luna) 로그(llm/providers/openai.py, llm/router.py)

| 레벨 | head | 필드 | step_id·reason |
| --- | --- | --- | --- |
| ERROR | openai api key is missing | 빠진 키 이름, hint | model_ready, key_missing |
| WARNING | openai request retry | status, error | 429 또는 5xx를 받아 한 번 더 보냄 |
| ERROR | openai request failed | reason, status, error(type/code), openai_req, model, ms, hint | luna_call |
| ERROR | openai response shape is unexpected | reason, ms | luna_call, shape |
| ERROR | unknown model | 모델 이름 | 등록되지 않은 모델 |
| WARNING | model marked down | model, device | model_ready, model_down |

- openai request failed의 reason은 http 사유(timeout, connect, http_4xx, http_5xx 등) 또는 concurrency_wait(동시 호출 상한 대기 초과)다.
- error는 OpenAI 오류 본문의 `type/code`만 남긴다. 예: rate_limit_exceeded, insufficient_quota. 메시지 원문은 남기지 않는다.
- openai_req는 응답 헤더 x-request-id 값이다.
- model marked down: 로컬 ocr·slm 준비 실패로 재시작 전까지 그 (모델, 장치)를 쓰지 않을 때 남긴다.

## Modal·로컬 모델 로그(llm/providers/modal_gpu.py, ocr.py, slm.py, core/logging.py)

| 레벨 | head | 필드 | 뜻 |
| --- | --- | --- | --- |
| INFO | modal state changed | from, to(idle\|deploying\|ready\|down) | Modal 엔진 상태 변화 |
| ERROR | modal lookup failed | reason, slot, hint | 토큰 확인·앱 조회 실패 → down |
| INFO | modal deploy started / done | app, ms | 버전 이름 앱이 없어 기동 때 자동 배포 |
| ERROR | modal deploy failed | app, reason, hint | 자동 배포 실패 → down |
| INFO / WARNING | modal warmup done / failed | app, ms 또는 error | 배포 직후 예열 1회 결과 |
| ERROR | modal call failed | method, reason, error, ms | 원격 pipe 실패 → luna |
| WARNING | image model unavailable | model, missing | 패키지 미설치 |
| ERROR | image model import failed | model, missing | 설치됐지만 import 실패. 스택 남김 |
| ERROR | ocr model load failed / ocr inference failed | device / bytes, type | OCR 로드·추론 실패 |
| ERROR | slm model load failed / slm inference failed | device / pairs, max_chars | openjev 로드·추론 실패 |

- modal call failed의 reason: timeout, auth, not_found, quota, permission, remote_error

## 모니터 프로세스 자체 로그(app/Server_Monitor_Bot)

app.Server_Monitor_Bot 로거의 로그는 모니터 수집 대상에서 빠진다(hooks/tap.py). 기동·리더 관련 head다.

| 레벨 | head | 뜻 |
| --- | --- | --- |
| WARNING | monitor disabled | 모니터가 켜지지 않음. reason: db_name(DB 이름이 ai_<stage> 형식 아님), missing_deps, buffer, start_failed |
| WARNING | analysis disabled | reason=AI_DB_URL missing |
| WARNING | db connect failed | AI DB 연결 실패. 재시도 간격을 2배씩 늘려 최대 60초 |
| WARNING | vector store unavailable | Qdrant 연결 실패 |
| WARNING | schema mismatch | expected, actual. 기록 적재만 하고 분석을 멈춤 |
| INFO / WARNING | leader acquired / leader lost | 리더 잠금 획득·상실 |
| INFO / WARNING | seed loaded / seed read failed | 지식 시드 적재 결과 |
| WARNING | rss limit exceeded | 분석 프로세스 RSS가 300MB를 넘어 멈춤 |

- 모니터가 꺼져도 API 서비스는 그대로 기동한다.
