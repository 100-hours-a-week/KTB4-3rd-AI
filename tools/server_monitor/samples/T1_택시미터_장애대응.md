# 택시미터 장애 대응 메모

## OpenAI 429 한도 초과

- 신호: 단계 luna_call, HTTP 상태 429, 오류 코드 rate_limit_exceeded.
- 택시미터 요청이 몰리는 저녁 6시~8시에 주로 생긴다.
- 대응: 조정 정책으로 동시 요청 수를 4에서 2로 낮추고 10분 뒤 지표를 다시 본다.
- 30분 넘게 이어지면 OpenAI 사용량 페이지에서 분당 한도를 확인하고 팀 채널에 알린다.

## OpenAI 응답 지연

- 신호: 단계 luna_call, 사유 timeout, 지연 44000ms 이상.
- 택시미터 사진이 큰 경우(4MB 이상) 지연이 늘어난다.
- 대응: 같은 시간대 다른 기능(영수증)도 느린지 먼저 본다. 둘 다 느리면 OpenAI 쪽 문제로 보고 기다린다.

## 이미지 객체 없음

- 신호: 단계 image_fetch, HTTP 상태 404.
- 사용자가 업로드를 취소한 뒤 요청이 들어온 경우가 대부분이다.
- 대응: Spring 업로드 로그에서 같은 request_id를 찾아 업로드 완료 여부를 확인한다.
